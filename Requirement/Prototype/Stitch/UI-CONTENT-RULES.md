# MineG MVP UI 内容约束与原型清理规则

状态：正式设计内容基线
核定日期：2026-07-31
适用范围：MineG 移动端全部 Stitch HTML 原型和后续三端实现

## 1. 用户和产品前提

- App 只服务两名固定用户：本人和对象。
- 当前不做推广、增长、获客、品牌背书或面向陌生用户的信任建设。
- UI 只承载当前 MVP 功能、当前任务状态和完成交互所必需的信息。
- “温暖家庭”“私人云”“安全空间”“珍贵回忆”等产品定位可以存在于内部需求说明中，但不能因为品牌氛围而成为页面上的标题、副标题、卡片、徽章、页脚或装饰图形。
- 不展示成员规模、家庭规模、云端照片总数、加入天数等没有对应 MVP 操作的数据。

## 3. 唯一保留判断

一个可见元素至少满足以下一项才能保留：

1. 让用户发起、取消、确认或返回一个 MVP 操作；
2. 展示当前任务的真实状态、结果或进度；
3. 解释用户当前为什么不能继续，并给出可执行的恢复方式；
4. 说明授权、付费流量、删除、恢复、退出等操作会直接产生的后果；
5. 收集完成当前操作所必需的输入；
6. 满足系统权限、服务协议、隐私政策或无障碍的强制要求；
7. 区分当前媒体的必要类型或归属，例如视频时长、共享者和回收站时长。

不满足以上任一条件的元素直接删除，不以“增强氛围”“建立信任”“视觉平衡”或“页面显得太空”为理由保留。

## 4. 必须删除的内容

### 4.1 安全、隐私和云存储背书

以下内容在不参与当前交互时全部删除，包括对应的盾牌、锁、云朵、爱心等装饰 Icon：

- “私有存储 · 安全传输”；
- “家庭私有云空间”“私人云”；
- “端到端加密保护”“已加密”“加密存储”；
- “完全私密且安全”“保护隐私安全”；
- “数据安全由隐私协议保护”；
- “你的家庭回忆很安全”；
- 仅用于强调私密、安全、云端或存储能力的提示卡、状态徽章和页脚。

服务端权限、HTTPS/TLS、私有 OSS、审计等仍属于技术要求，但不在普通页面中作为卖点重复展示。

### 4.2 推广和情绪化文案

- 品牌口号、产品承诺、信任背书和“珍贵回忆”式宣传语；
- 面向多代家庭、家庭创建者或大规模成员的叙事；
- 对完成当前任务没有帮助的欢迎语、说明语和重复副标题；
- 仅为填充留白而存在的插画、装饰环、氛围卡片和说明区。

### 4.3 无操作价值的数据和菜单

- 云端照片总数、关联家庭成员数、加入天数等统计；
- MVP 不提供的隐私与安全中心、存储空间管理、容量套餐、同步频率等入口；
- 列表标题已经明确时，重复解释同一入口的副标题；
- 弹层背景中虚构的角色、统计、菜单或账号信息。

## 5. 必须保留的交互信息

“安全、存储、备份、隐私”等词不是机械禁词。以下内容会直接影响操作，必须保留并写得简短：

- 相册权限用途、当前权限不足以及去系统设置授权的操作；
- 扫描中、上传中、等待 Wi-Fi、网络离线、服务不可用、同步完成和进度；
- 使用移动网络可能产生流量费用；
- 下载原文件、保存成功、保存失败及失败后的重试或取消；
- 退出登录会停止未完成备份；
- 移入回收站会隐藏媒体但不删除设备本地媒体；
- 回收站内容的保留方式、可恢复性和恢复后的共享状态；
- 登录前的服务协议与隐私政策勾选。

文案只描述当前事实、影响和下一步，不追加安全承诺或品牌口号。

## 6. 当前设计的已知清理点

| 功能域 | 删除或收敛内容 | 保留内容 |
|---|---|---|
| 登录 | 页脚“私有存储 · 安全传输”及锁/盾牌装饰 | 手机号、密码、协议勾选、登录和错误反馈 |
| 注册 | “家庭私有云空间”等宣传式审核说明 | 注册字段、校验错误和“注册后需审核”这一必要事实 |
| 待审核 | 隐私安全承诺、存储珍贵记忆、无后端事实支撑的通知背书 | 审核状态、刷新、重新登录、退出 |
| 相册权限 | “完全私密且安全”等卖点卡；与授权无关的家庭共享宣传 | 为什么需要完整权限、继续授权、暂不开启 |
| 私人空间 | 存储摘要、安全/同步背书和无操作价值统计 | 私人/共享 Tab、媒体网格和媒体类型标识 |
| 媒体详情 | 加密命名、加密徽章或安全说明 | 下载、共享/取消共享、删除及真实反馈 |
| 备份设置 | 私人空间安全说明、存储/容量卖点、重复说明 | 自动备份、移动网络备份及流量影响 |
| 备份状态 | 不影响操作的云端/安全宣传 | 阻塞原因、真实进度、完成状态和恢复操作 |
| 回收站 | “私密存储提示”“保护隐私安全”等标题和背书 | 保留规则、已删除时长、恢复操作和恢复后果 |
| 个人中心 | 安全页脚、统计、加入天数、无 MVP 能力的菜单和重复副标题 | 资料、备份设置、回收站、我分享的、帮助反馈、退出 |
| 确认弹层 | 背景中虚构的统计、角色和安全中心 | 当前确认事项、直接后果、确认和取消 |

## 7. 设计与验收要求

- 所有 32 个有效 `index.html` 都要按本规则检查。
- 页面内容只修改 `index.html`，不再生成或维护配套静态参考图。
- 删除元素后重新整理间距和层级，不新增替代宣传语、装饰卡或占位插画。
- 空状态只保留状态名称、必要说明和可执行操作；没有操作时可以只显示简短状态。
- 图标按钮可以不显示文字，但必须保留准确的无障碍名称。
- 设计验收逐项询问：“删除该元素会不会让用户无法操作、误判当前状态或不了解直接后果？”如果不会，就删除。
