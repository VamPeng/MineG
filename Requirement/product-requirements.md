# 私人家庭相册 App 产品需求

## 1. 文档信息

- 项目名称：MineG
- 文档版本：v1.1
- 文档状态：MVP 产品需求基线
- 整理日期：2026-07-24
- 项目目标：为本人和家人提供一个拥有私人空间和家庭共享空间的个人相册 App。
- 本轮结论：产品需求确认完成，可以进入技术需求分析。
- 未包含内容：技术栈、系统架构和 UI 视觉设计。
- v1.1 变更：明确“原文件”指媒体内容质量无损，不要求文件字节和全部非必要元数据完全一致。

## 2. MVP 原则

MVP 聚焦媒体的上传、浏览、私人下载、共享和逻辑删除，不加入非必要的管理、互动、搜索和容量控制功能。

### 2.1 核心用户价值

- 家庭成员能够自动备份设备相册，避免原始媒体丢失。
- 每位成员拥有默认私密的个人空间。
- 成员可以主动将单张媒体共享给全家浏览。
- 云端媒体和设备本地媒体相互独立，任何一端的删除不影响另一端。

### 2.2 产品边界

- MineG 是单个固定家庭使用的私人系统，不是公开注册的社交相册平台。
- MVP 优先保证原文件保存、访问隔离和备份可靠性。
- 未在本文档中明确列出的扩展能力，不自动进入 MVP。

## 3. 用户与家庭

### 3.1 家庭模型

- 系统只服务一个固定家庭。
- 不支持创建、加入或切换多个家庭。
- 每位家庭成员拥有独立账号和独立私人空间。
- 每位成员可以将私人空间中的单张媒体共享到家庭相册。
- 未共享的私人媒体不能被其他家庭成员看到。

### 3.2 注册与登录

- 用户使用手机号和密码注册、登录。
- 不使用短信验证码。
- 新注册账号初始状态为“待审核”。
- 只有后台人工审核通过后，账号才能进入 App。
- 后台审核权限仅用于通过新注册账号，不能查看成员的私人媒体。
- MVP 不提供忘记密码、自助找回密码、后台重置密码和修改密码功能。
- MVP 不提供已审核账号的停用或删除功能。

### 3.3 用户资料

- 完整手机号仅用于注册和登录，不作为公开展示名称。
- 注册时，用户昵称默认为手机号后四位。
- 用户可以在个人页面修改自己的昵称和头像。
- 家庭相册等页面展示昵称和头像，不展示完整手机号。
- MVP 不支持修改登录手机号。

## 4. 媒体范围与原文件

- 支持设备相册能够提供的常见媒体，包括照片、视频、GIF、iPhone 实况照片等。
- “原文件”在本产品中指媒体内容质量无损，不要求上传文件与设备文件逐字节一致或文件哈希一致。
- 不得对原始媒体进行降低质量的重压缩、缩放、降分辨率、降帧、降低音视频码率或有损转码。
- 默认保留原始媒体格式、画面、帧、音频、色彩和动态内容。
- 必须保留正确显示和播放所必需的信息，例如图片方向、色彩和 HDR 信息、视频编解码与时序信息、实况照片资源关联等。
- GPS 等非必要位置元数据不属于必须保留范围，MVP 不读取、不展示、不搜索照片位置，也不为保留照片位置单独申请额外权限。
- 具体格式兼容清单在技术需求分析阶段确定。
- 缩略图需求暂时只保留占位；是否使用 OSS 图片处理、支持哪些格式以及具体规格后续讨论。

## 5. 自动备份

### 5.1 备份范围

- 自动备份覆盖设备相册中的全部媒体。
- 首次开启备份时，需要备份设备中已有的全部历史媒体。
- 后续持续发现并备份设备相册中新产生的媒体。
- 只要设备相册中出现新的媒体条目，无论来自拍摄、编辑导出、下载或其他 App 保存，都应进入备份范围。
- 不提供由用户选择特定系统相册或目录的功能。

### 5.2 相册组织

- 备份时参考设备自身的相册文件夹或相册名称。
- 云端按设备相册的同名方式组织媒体。
- 不为多设备上的同名相册增加特殊合并规则，按照上述同名同步原则执行。
- 具体平台上的相册、目录和媒体归属差异留待技术分析。

### 5.3 去重

- 系统需要避免同一账号因重复扫描、备份重试或同一设备重复上传而保存重复媒体。
- MVP 不要求在不同家庭成员账号之间进行内容去重。
- 即使不同账号上传了内容相同的媒体，也按各自独立的媒体记录管理。
- 具体去重标识和算法留待技术需求分析。

### 5.4 网络策略

- 自动备份默认仅使用 Wi-Fi。
- 用户可以主动开启移动网络备份。
- App 进入后台后的持续备份、系统中断后的恢复和断点续传属于待分析的技术需求，产品阶段暂不承诺具体行为。

### 5.5 设备与云端的独立性

- 手机系统相册与云端相册相互独立。
- 用户删除手机本地媒体时，不删除云端备份。
- 用户删除云端媒体时，不删除手机本地媒体。
- 自动备份只处理设备中尚未成功备份的新媒体。

## 6. 私人空间

- 自动备份的媒体默认进入上传者的私人空间。
- 其他家庭成员不能查看未共享的私人媒体。
- 用户可以浏览自己的私人媒体。
- 用户可以下载自己私人空间中的原始文件。
- 用户可以删除自己私人空间中的媒体，删除采用逻辑回收站策略。

## 7. 家庭相册

### 7.1 共享

- MVP 只支持共享单张媒体。
- MVP 不支持共享整个相册。
- 用户主动共享后，该媒体出现在家庭相册中。
- 用户取消共享后，该媒体立即从家庭相册消失，但仍保留在上传者的私人空间中。

### 7.2 浏览限制

- 家庭成员可以在 App 内全屏查看共享照片。
- 家庭成员可以在 App 内在线播放共享视频。
- 家庭相册不提供原文件下载。
- 家庭相册不提供保存到设备、导出或二次分享入口。
- 产品只能限制功能入口，不能承诺绝对阻止截屏、录屏或通过技术手段提取已经显示的数据。

### 7.3 互动

- MVP 不提供点赞。
- MVP 不提供评论。
- MVP 不提供其他社交互动功能。

## 8. 删除与逻辑回收站

### 8.1 App 内删除

- 用户删除媒体时，媒体进入逻辑回收站。
- 逻辑回收站通过数据库状态实现，不在 OSS 中移动或复制原文件。
- 原文件在人工永久清理前始终保留在 OSS 原位置。
- 被删除的媒体立即从私人空间的正常浏览列表中隐藏。
- 如果媒体此前已共享，则删除后立即从家庭相册隐藏。
- 用户可以从逻辑回收站恢复媒体。

### 8.2 回收站时间

- 记录媒体首次进入回收站的准确时间 `trashed_at`。
- `trashed_at` 写入后保持不变，不能每天覆盖为当天时间。
- 媒体已在回收站放置的天数由当前时间与 `trashed_at` 计算。
- 当前不设置 3 天或其他自动到期时间。
- 回收站媒体一直保留，直到人工执行永久清理。

### 8.3 人工永久清理

- 在线 App 不自动物理删除 OSS 原文件。
- 在线应用角色不拥有 OSS 永久删除权限。
- 永久清理由独立的人工运维流程执行。
- 人工清理需要支持按照进入回收站的时间、时间范围、用户、媒体类型等条件筛选。
- 永久清理前应生成待删除清单，展示文件数量、总容量和筛选范围。
- 人工确认后才能使用独立运维权限删除 OSS 原文件。
- 清理完成后记录实际清理时间 `purged_at` 并保留操作记录。

## 9. MVP 明确不做

- 多家庭创建、加入和切换。
- 复杂家庭管理员权限。
- 查看其他成员的私人媒体。
- 已审核账号的停用和删除。
- 短信验证码。
- 忘记密码、密码找回、后台重置和密码修改。
- 修改登录手机号。
- 整个相册共享。
- 家庭相册下载、保存、导出和二次分享。
- 点赞、评论等互动。
- 搜索、按日期筛选、按文件名筛选和按媒体类型筛选。
- 每位成员独立存储配额。
- App 自动永久删除 OSS 原文件。
- UI 视觉和页面布局的详细设计。

## 10. MVP 验收标准

以下项目全部满足时，MVP 产品功能视为达到本文档定义的范围：

- [ ] 用户能够使用手机号和密码提交注册。
- [ ] 未审核账号不能进入 App，审核通过后可以正常使用。
- [ ] 用户能够修改自己的昵称和头像，其他成员看不到其完整手机号。
- [ ] 首次备份能够发现设备相册中的全部历史媒体。
- [ ] 后续备份能够发现设备相册中新产生且尚未成功备份的媒体。
- [ ] 重复扫描或上传重试不会在同一账号中产生重复媒体。
- [ ] 上传后的原始媒体保持画面、帧、音频、分辨率、色彩、动态内容和播放质量，不因预览、缩略图或元数据处理发生质量损失。
- [ ] 自动备份的媒体默认只能由上传者查看。
- [ ] 用户能够浏览并下载自己私人空间中的原文件。
- [ ] 用户能够把单张媒体共享到家庭相册，也能够取消共享。
- [ ] 家庭成员能够全屏浏览共享照片和在线播放共享视频。
- [ ] 家庭相册不提供下载、保存、导出和二次分享入口。
- [ ] 用户能够把自己的媒体移入逻辑回收站并进行恢复。
- [ ] 进入回收站的媒体立即从正常私人视图和家庭相册隐藏。
- [ ] App 删除云端媒体不会删除设备本地媒体，设备本地删除也不会删除云端媒体。
- [ ] 在线应用不能物理删除 OSS 原文件。

## 11. 待技术需求分析

- 客户端目标平台范围。
- 各平台自动发现历史媒体和新增媒体的能力与限制。
- 后台备份、任务恢复、失败重试和断点续传。
- 上传协议、并发策略和移动网络控制。
- 原文件与编辑后媒体的识别方式。
- 去重算法及备份完成状态的判定。
- 设备相册名称、目录和多相册归属的跨平台映射。
- 照片、视频、GIF、实况照片等格式兼容清单。
- OSS 对图片缩放、视频预览及私有签名访问的支持范围。
- 缩略图与预览文件策略。
- 私人下载和家庭只读浏览的权限控制。
- 数据库模型和逻辑回收站实现。
- 人工永久清理工具、预览清单、确认流程与审计记录。
- 从回收站恢复后是否恢复此前的家庭共享状态。
- 安全、备份、监控、部署方式与技术栈。

这些项目决定“如何实现”，但不阻塞本轮产品需求基线完成。技术分析发现平台限制时，应回到本文档记录受影响的产品行为和最终取舍。

## 12. 需求变更规则

- v1.1 是当前 MVP 产品需求范围基线。
- 后续新增功能先记录为候选需求，不直接加入 MVP。
- 修改默认隐私、原文件保存、家庭下载限制或物理删除权限等安全边界时，必须明确说明影响并重新确认。
- 技术实现限制如果导致产品行为变化，需要同步更新本文档和版本号。
- 产品需求、技术需求、部署配置和 UI 设计分别维护，避免相互替代。
