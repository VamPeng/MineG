- 文档版本：v0.3

- 创建日期：2026-07-24

## 3. 当前讨论

### 3.1 运行目标

- Android 10（API 29）及以上
- iOS 13 及以上
- HarmonyOS 6.0 及以上

状态：目标平台和最低系统版本已确认。最低系统版本不等于编译或上架使用的目标 SDK；目标 SDK 使用开发和发布时仍受平台支持且满足应用商店要求的稳定版本。

### 3.2 技术栈

状态：基础技术栈已确认。

按照以下顺序逐项确定：

1. 客户端 UI 技术栈。
2. 客户端数据层技术栈。
3. Android 原生能力技术栈。
4. iOS 原生能力技术栈。
5. HarmonyOS 原生能力技术栈。
6. 后端服务技术栈。
7. Web 管理端技术栈。
8. 数据库、缓存与对象存储。

部署方式、ECS 规格、操作系统、容器、入口代理、发布流程和云资源费用不在本文档中确定，后续由独立部署配置或部署文档管理。

#### 3.2.1 客户端 UI

- 三端分别使用平台原生应用技术栈，不再使用 Flutter，也不保留 Dart UI 或 Dart FFI 接入层。
- Android 使用 Kotlin 和 Jetpack Compose，作为首个完整业务参考实现。
- iOS 使用 Swift；SwiftUI 与 UIKit 的具体使用边界在 iOS 实施前根据 iOS 13 最低版本和页面能力确认。
- HarmonyOS 使用 ArkTS 和 ArkUI。
- 三端 UI、导航、页面生命周期和纯展示状态分别原生实现；跨平台统一的是数据核心、业务状态机、接口语义和验收行为，不要求共享 UI 代码。
- 业务开发顺序为 Android、iOS、HarmonyOS；但在扩大 Android 业务代码规模前，必须先完成共享核心在三端的最小接入验证，避免在 Android 完成后才发现其他平台工具链不可用。
- Android 是第一套参考实现，不是跨平台契约本身。Android 特有的类、URI、任务对象和生命周期语义不得直接写入公共契约。

状态：已确认。

#### 3.2.2 平台能力与契约边界

状态：架构归属已确认，A1 至 A12 是功能实现阶段的候选清单，具体业务范围和实现方案待逐项确认。

以下能力依赖 Android、iOS 和 HarmonyOS 的系统服务，不能假定由通用 C++ 数据核心直接替代。三端必须按公共平台契约提供语义一致的能力，但内部实现和系统对象可以不同。

| 相册与媒体库 | MediaStore | PhotoKit | Media Library Kit |

| 后台任务 | WorkManager、系统任务或前台服务 | BackgroundTasks、后台 URLSession、PhotoKit 后台能力 | Background Task Kit、系统上传下载任务 |
| 文件与沙盒 | 应用目录、Scoped Storage、文件选择器 | App Sandbox、FileManager、文件选择器 | Core File Kit、应用沙盒、文件选择器 |
| 安全存储 | Android Keystore | Keychain | Asset Store Kit |
| 网络状态 | ConnectivityManager、计量网络状态 | Network framework、受限或昂贵网络状态 | 系统网络连接状态 |
| 通知与任务进度 | Notification、前台任务通知 | UserNotifications | 系统通知服务 |
| 媒体解码与播放 | 系统图片解码、视频播放器 | Image I/O、AVFoundation、Live Photo | Image Kit、Media Kit |
| App 生命周期 | 前后台、终止、重启和系统调度回调 | 前后台、挂起、终止和系统调度回调 | UIAbility 生命周期和系统调度回调 |

##### A. 首版必需的系统桥接

###### A1. 相册权限

- 查询当前相册权限状态。
- 发起系统权限请求。
- 区分完整授权、部分或受限授权、拒绝和系统限制。
- 检测授权在系统设置中被修改。
- 必要时跳转到当前 App 的系统设置页。
- Android 和 HarmonyOS 需要根据目标系统版本处理媒体权限差异。

###### A2. 相册、目录和媒体条目读取

- 枚举设备相册、目录或媒体集合。
- 枚举照片、视频、GIF、实况照片及平台可识别的其他媒体。
- 读取平台本地媒体标识。
- 读取原始文件名、媒体类型、格式、尺寸、时长、创建时间和修改时间。
- 读取一条媒体所属的一个或多个设备相册。
- 判断资源是否只存在于云端、尚未下载到本机或当前不可读取。
- 分页或分批读取大量媒体，避免一次性把完整媒体库加载到内存。

###### A3. 原始媒体资源访问

- 获取可读取的原始资源句柄、URI、文件描述符或临时文件。
- 支持以流或文件方式把原始字节交给上传层。
- 处理一条逻辑媒体对应多个底层资源的情况。
- iOS 需要识别 RAW+JPEG、实况照片的照片与配对视频、编辑前后资源及调整数据。
- 处理系统云相册中的原始资源下载。
- 支持取消读取，并在系统中断后重新请求资源。
- 原始资源访问完成后正确释放系统句柄和临时文件。
- “原始”以媒体内容质量无损为准，不要求与设备文件逐字节一致或哈希一致。
- 不允许降低质量的重压缩、缩放、降分辨率、降帧、降低音视频码率或有损转码。
- 必须保留图片方向、色彩和 HDR、视频编解码与时序、实况照片资源关联等正确显示和播放所需信息。
- GPS 等非必要位置元数据不属于必须保留范围；系统桥接不单独读取、提取、索引或展示位置，也不为保留位置单独申请额外权限。
- 不为删除 GPS 等非必要元数据而重写媒体文件；直接上传系统在正常相册权限下提供的媒体字节。
- 不同平台是否在返回媒体时保留位置元数据，不影响 MVP 验收。

###### A4. 相册增量变化

- 监听 App 运行期间的媒体库变化。
- 获取自上次扫描标记之后新增、修改或删除的媒体。
- 在 App 再次启动或恢复运行时进行增量补扫。
- 处理平台媒体标识失效、媒体内容被重新编辑和相册归属变化。
- 系统变化事件只作为触发信号，最终状态仍需通过补扫核对。

###### A5. 缩略图和预览

- 请求适合相册网格的系统缩略图或低分辨率预览。
- 取消已离开可视区域的缩略图请求。
- 区分缩略图、预览资源和需要永久保留的原始资源。
- 避免在 C ABI 或平台绑定层之间复制传递超大原图字节，优先交换文件描述符、受控句柄、路径或流式读取能力。
- 支持照片、GIF、视频封面和实况照片的可视预览。

###### A6. 后台运行与系统调度

- 注册、启动、取消和恢复系统后台任务。
- 接收系统授予执行机会、即将超时、被停止和任务完成等回调。
- 在系统允许时恢复相册扫描和上传队列。
- Android 和 HarmonyOS 如使用长时间可见任务，需要管理系统要求的任务通知。
- iOS 后台传输和系统调度的生命周期不能只依赖前台页面或共享数据核心持续存活。
- 设备重启、App 升级或进程被回收后，能够重新关联尚未结束的系统任务。

###### A7. 网络条件与系统传输

- 获取当前是否联网。
- 区分 Wi-Fi、蜂窝网络、计量网络、受限网络和漫游等系统可提供的状态。
- 响应网络切换和断网恢复。
- 把“默认仅 Wi-Fi”和“允许移动网络”转换为系统任务约束。
- 支持由系统托管的后台上传和下载，并接收进度、完成、取消和失败回调。
- 前台网络请求与系统后台传输需要使用同一套服务端任务标识、幂等语义和持久化状态机。

###### A8. App 文件与磁盘

- 获取 App 私有数据、缓存和临时目录。
- 创建、读取和清理媒体暂存文件。
- 查询可用磁盘空间，并处理空间不足。
- 防止仍被系统后台任务使用的暂存文件被提前清理。
- 按平台要求设置文件保护、备份排除或共享容器。
- 打开系统文件选择器或保存位置选择器的能力保留为平台接口。

###### A9. 安全凭据与设备安装标识

- 在系统安全存储中保存访问令牌、刷新令牌和本机密钥。
- 生成并持久化 App 安装级标识，不使用不可重置的硬件标识。
- 退出登录时清除账号凭据，并停止账号关联的后台任务。
- C++ 数据层只接收短期可用的数据或调用抽象接口，不直接绕过系统安全存储。

###### A10. 媒体展示与播放

- 全屏显示照片和 GIF。
- 播放、暂停、拖动和停止视频。
- 处理系统音频焦点、静音状态、耳机和前后台切换。
- 在支持的平台上展示实况照片，或采用后续确认的降级形式。
- 媒体播放器生命周期必须与页面和 App 生命周期正确绑定。

###### A11. App 生命周期和任务状态回传

- 接收 App 启动、进入前台、进入后台和即将终止等事件。
- 获取应用版本、系统版本和必要的运行环境信息，用于兼容判断和问题定位。
- 将系统任务状态持续回传给共享数据核心，并由各端原生 UI 订阅可展示状态。
- 系统层回调不能只保存在内存中；关键结果必须写入可恢复的持久状态。

###### A12. 私人原文件保存到系统相册

- 用户下载本人私人空间的原文件后，将文件写入设备系统相册。
- 根据平台要求申请向系统相册添加媒体的权限。
- 保存照片、视频、GIF 和实况照片时保留平台能够写入的完整资源组成和格式。
- 系统相册保存成功前，App 不显示下载完成。
- 保存失败时向 App 内返回明确状态，不改为调用系统分享面板。
- 下载产生的新系统相册条目不能被自动备份流程再次保存为重复云端媒体；具体识别方式在去重方案中确定。

##### B. 当前不需要接入

- 相机拍摄和麦克风录音。
- 联系人和短信。
- 持续定位。
- 单独读取、提取、索引或展示照片中的 GPS 位置元数据。
- 仅为保留照片位置元数据申请额外系统权限。
- 蓝牙和附近设备。
- 日历和健康数据。
- 由业务主动发送的本地系统通知和远程推送；备份状态只在 App 内展示。
- Face ID、Touch ID、指纹或人脸等生物识别解锁。
- 从 MineG 调用系统分享面板，把媒体发送给其他 App。
- 把 MineG 注册为系统相册或其他 App 的分享接收目标。
- 让用户通过系统文件选择器指定私人原文件的下载位置。
- 家庭相册媒体的系统分享、保存或导出。

如果后续新增这些能力，需要重新评估权限、隐私说明和平台审核影响。

说明：如果后续选定的 Android 或 HarmonyOS 后台任务类型被系统强制要求显示任务通知，该通知属于系统运行约束，不属于上述业务通知或远程推送。

#### 3.2.3 共享数据层方向

状态：技术栈、职责边界和平台契约方向已确认，具体命令、查询、事件和错误结构在功能实现方案中确定。

- 共享数据核心使用 C++17 实现，并通过稳定 C ABI 接入 Kotlin、Swift 和 ArkTS。
- C++ 数据核心是客户端业务数据、媒体索引、同步任务和可恢复状态的唯一真实来源。
- C++ 数据核心负责：领域数据模型、SQLite Schema 与 Migration、事务、Repository、媒体索引、同步与上传队列、业务状态机、API 契约、分页、去重、幂等、完整性校验、错误归类以及 UI 所需的聚合数据状态。
- 三端原生应用不得建立并行业务数据库，也不得各自复制维护备份任务、上传进度、同步状态机或服务端确认规则。
- 三端原生 UI 可以保留页面生命周期、动画、输入框、导航选择和临时筛选条件等纯 UI 瞬时状态。
- 原生应用通过公共的命令、查询和事件订阅接口调用数据核心，不直接修改核心数据库。
- 数据核心通过平台能力接口使用 `MediaSourcePort`、`CredentialStorePort`、`BackgroundSchedulerPort`、`TransportPort`、`ConnectivityPort` 和 `FilePort` 等系统能力；具体名称可在接口设计时调整，但职责边界必须保持。
- 数据核心决定“处理什么、何时处理、状态如何流转、失败后如何恢复”；平台适配器负责“如何调用当前系统完成相册读取、安全存储、后台调度和实际传输”。
- C++ 数据核心不能直接持有只在单个平台生命周期内有效的相册对象、URI、权限弹窗、后台任务实例、传输实例或播放器实例。
- 平台层与数据核心之间只交换可序列化或所有权明确的数据，例如不透明平台标识、文件描述符、受控句柄、路径、请求描述、任务标识、进度和结果。
- 平台媒体条目必须转换成公共 `MediaDescriptor` 语义；Android 的 MediaStore 字段和 URI 不能成为 iOS、HarmonyOS 必须模拟的公共模型。
- 系统安全存储中的原始令牌和密钥不复制到普通 C++ 数据库；数据核心通过凭据接口按需获取短期可用数据。
- 平台后台任务产生的关键结果必须先提交给数据核心并持久化，再通知原生 UI 更新界面。
- 数据核心负责生成 API 请求语义、解析业务响应、编排 OSS 分片任务、维护重试和服务端核对状态；实际 HTTP 和文件传输由 `TransportPort` 执行。
- 系统要求脱离 App 进程托管的后台传输由 Kotlin、Swift 或 ArkTS 平台适配器执行；数据核心继续负责业务任务定义、持久状态、幂等和结果核对。
- 是否增加媒体内容的应用层加密属于后续安全与媒体传输功能方案，不由共享核心语言选择提前决定。
- C ABI、数据库格式、平台契约和核心行为测试必须与 UI 技术栈解耦，为未来按模块替换实现保留可能；这不代表规划在 MVP 后必然改用其他语言。

#### 3.2.4 Web 管理端范围

状态：MVP 范围和基础技术栈已确认。

- Web 管理端是内部使用的账号审核工具，不是面向家庭成员的网页版相册。
- MVP 只提供管理员登录、查看待审核账号和通过注册申请。
- Web 管理端不能查看成员的私人媒体。
- 人工永久清理不进入首版 Web 管理端。
- 人工永久清理作为独立运维工具，在后续功能实现技术方案中单独讨论权限、预览、确认和审计机制。
- Web 管理端采用 Vue 3、TypeScript、Vite 和 Element Plus。
- Web 管理端构建为普通客户端单页应用（SPA），不使用 SSR。
- 首版使用 Vue Router 管理页面路由，使用轻量 HTTP 请求封装访问后端 API。
- 首版不引入复杂全局状态管理框架；确有跨页面业务状态需求时再评估。
- Rust/WASM 前端在技术上可行，但当前需求没有性能或代码复用收益，不作为 MVP 方案。

#### 3.2.5 后端整体形态

状态：已确认。

- 后端采用模块化单体架构，对移动端 App 和 Web 管理端提供统一 API。
- 认证与账号、注册审核、用户资料、媒体元数据、上传任务、私人空间、家庭共享、逻辑回收站、对象存储适配和审计记录在同一后端项目中按模块划分。
- 业务数据、权限状态、媒体元数据和任务状态存入 PostgreSQL。
- 原始媒体存入私有对象存储，不设置永久公开访问地址。
- App 先向后端申请上传或访问授权，再使用短期凭证或签名 URL 直接与对象存储传输原始媒体。
- 后端负责验证账号、媒体归属、访问权限、对象键和上传完成状态，原则上不代理完整照片或视频流量。
- 分片上传、断点续传、对象完整性验证和签名有效期在上传协议方案中进一步确定。
- 如果后续需要缩略图、视频预览或耗时校验，优先在同一代码库中增加独立 Worker 进程。
- MVP 不采用微服务、Kubernetes、服务发现、分布式事务、API Gateway 或 Kafka 等消息系统。

#### 3.2.6 后端语言与 Web 框架

状态：后端基础语言已确认，HTTP 框架和基础组件继续逐项确定。

- 后端使用 Go 实现。
- 使用开发和发布时仍受官方支持的稳定 Go 版本，并在项目和构建环境中锁定版本。
- 后端继续采用已确认的模块化单体边界，不因为选择 Go 而提前拆分服务。
- 业务模块、领域规则和数据库事务不能直接耦合到具体 HTTP Router 或 Web 框架。
- HTTP Router 或 Web 框架需要支持标准 `net/http` 生态、Middleware、路由参数、请求取消、超时、测试和优雅关闭；具体选择后续单独确认。
- JSON 编解码、参数验证、错误映射、日志、追踪、配置和 OpenAPI 生成组件在对应技术主题中逐项确定。
- PostgreSQL 访问、SQL 代码生成、Migration 和连接池方案在数据库主题中继续确定。
- 阿里云 OSS、STS 和 ECS 实例 RAM 角色优先使用阿里云仍受支持的 Go SDK，不自行保存长期 AccessKey。
- Go 只用于后端，不改变已确认的 Web 管理端方案；Web 管理端仍使用 Vue 3 和 TypeScript。

#### 3.2.7 后端关系型数据库

状态：PostgreSQL 和数据库约束已确认，原 SQLx 接入方案已被替代，Go 数据库组件待确认。

- 后端使用 PostgreSQL。
- Go 后端使用参数化原生 SQL，不引入以隐藏 SQL 和事务边界为主要工作方式的全功能 ORM。
- PostgreSQL Driver、连接池、静态 SQL 代码生成或查询映射组件待后续确认。
- 数据库 Migration 使用独立、可在 CI 和部署流程中执行的 SQL Migration 工具；具体工具待后续确认。
- 已经进入共享环境的 Migration 只允许追加修正，不直接修改历史文件。
- 账号、权限、媒体归属、共享、逻辑回收站和上传任务等跨记录状态必须使用数据库事务和约束保证一致性。
- 核心业务字段使用明确的关系型列和约束；JSONB 只用于确实无法稳定建模的扩展元数据，不能替代核心表结构。
- 原始媒体、缩略图和视频文件不存入 PostgreSQL，只保存对象存储键、校验信息、资源关系和业务元数据。
- MVP 只使用一个业务数据库，不按模块拆库。
- PostgreSQL 具体大版本在部署环境确定时锁定为当时仍受支持的稳定版本。

#### 3.2.8 缓存

状态：已确认。

- MineG MVP 不使用 Redis，也不部署其他独立缓存服务。
- PostgreSQL 是账号、权限、媒体、共享、逻辑回收站和任务状态的唯一真实来源。
- 不使用缓存保存唯一任务状态或作为权限判断的唯一依据。
- 允许在 Go 进程内缓存可随时重建、丢失后不影响正确性的对象，但不将其视为独立技术组件。
- 如果未来出现多实例协调、经过测量的数据库热点或跨实例限流等明确需求，再重新评估独立缓存。

#### 3.2.9 对象存储

状态：基础方案已确认，上传协议细节待讨论。

- 文件上传后的最终持久化目标是阿里云对象存储 OSS。
- OSS Bucket 必须保持私有并阻止公共访问，不能为媒体提供永久公开地址。
- 原始媒体不存入 PostgreSQL，也不在后端服务器磁盘上保留长期副本。
- App 经 MineG 后端鉴权后，使用范围受限且自动过期的 STS 临时凭证直接向 OSS 上传。
- 大文件使用 OSS 分片上传能力，为移动网络中断后的断点续传保留基础。
- 浏览、播放和私人下载由后端先完成业务权限检查，再签发短期有效的访问地址。
- OSS 默认使用 HTTPS，并开启 SSE-OSS AES-256 服务端加密。
- 在线后端运行身份不授予永久删除原文件的权限；永久删除使用独立人工运维身份。
- 已完成上传的原文件对象不可覆盖。对象键由后端生成，不能直接信任客户端提供的路径。
- OSS 生命周期规则不得自动删除已完成的原文件；可以用于清理长期未完成的废弃上传分片。
- MVP 不引入 CDN。
- STS 权限策略、对象键结构、分片大小、并发数、完成校验和失败清理在上传协议技术方案中确定。

#### 3.2.10 三端原生应用与核心绑定

状态：已确认。

- Android 应用、系统能力适配和页面逻辑使用 Kotlin；UI 使用 Jetpack Compose。
- iOS 应用、系统能力适配和页面逻辑使用 Swift；需要连接 C++ 或兼容 Objective-C API 时允许增加 Objective-C++ 薄封装。
- HarmonyOS 应用、系统能力适配和页面逻辑使用 ArkTS；UI 使用 ArkUI。
- 三端调用 C++17 共享数据核心时统一依赖稳定 C ABI，不让 Kotlin、Swift 或 ArkTS 直接依赖 C++ 类和 STL 类型。
- Android 通过 JNI 薄封装接入 C ABI。
- iOS 通过 C/Objective-C++ 薄封装和 Swift 可调用接口接入 C ABI。
- HarmonyOS 通过 Node-API 薄封装接入 C ABI。
- 三端绑定层只负责类型转换、异步回调和生命周期衔接，不复制 Repository、状态机、去重、重试或业务授权逻辑。
- 系统后台回调需要持久化关键状态时，平台适配器可以直接调用 C ABI 写回共享数据核心，不能依赖页面存活。
- 绑定层的命令、查询、事件、错误码和资源释放行为需要形成版本化契约，并由同一组契约测试验证。

#### 3.2.11 客户端本地数据库

状态：已确认。

- C++ 数据核心使用 SQLite 作为 Android、iOS 和 HarmonyOS 的统一客户端本地数据库。
- 直接使用 SQLite C API，并在 C++ 内建立轻量 RAII 封装；不引入移动端 ORM。
- SQLite 源码采用固定版本并随 C++ 核心统一构建，不依赖各平台可能不同版本的系统 SQLite。
- 数据库位于 App 私有数据目录，只保存业务数据、媒体索引、同步队列和可恢复任务状态，不保存媒体原始字节。
- 启用 WAL 模式和外键约束；每次创建连接时显式执行 `PRAGMA foreign_keys = ON`。
- 首版使用一个专用数据库执行线程串行处理写入；所有写入必须通过明确事务，不能从原生 UI、JNI、Objective-C++、Node-API 或系统回调直接并发写库。
- 读取默认也通过数据核心的数据库执行器调度；只有经过性能测量确认存在瓶颈时才增加只读连接。
- 数据库 schema 使用整数版本号和按顺序执行的嵌入式 SQL migration；migration 必须在事务中完成，已经发布的历史 migration 不直接修改。
- MVP 不使用 SQLCipher。登录凭据和密钥继续存入各平台安全存储；如后续确认本地业务数据库需要额外加密，再单独评估。

#### 3.2.12 客户端数据传输层

状态：架构边界已确认，三端具体 HTTP 实现和上传参数待功能方案及最小验证确定。

- 数据核心通过统一 `TransportPort` 发起业务请求和文件传输，不把某个网络库的对象或回调类型暴露到领域模型。
- C++ 数据核心负责构造平台无关的请求描述、解析 API JSON、编排 OSS 分片任务、维护取消、进度、重试、幂等和可恢复状态。
- API JSON 使用固定版本的 nlohmann/json 解析和生成；核心领域模型不能直接依赖 JSON 对象作为长期内部表示。
- `TransportPort` 负责实际执行 HTTPS、上传或下载，并返回统一的响应、进度和错误分类。
- 前台请求可以由三端平台网络实现执行；如果后续选择 libcurl 等可移植库，也只能作为 `TransportPort` 的一种实现，不能绕过平台契约或成为公共业务模型的一部分。
- iOS 后台 URLSession、Android 系统后台任务及 HarmonyOS 系统托管传输等必须由系统接管的能力，由对应平台 `TransportPort` 适配器执行。
- 平台传输完成、取消或失败后，必须使用稳定任务标识把结果写回 C++ 数据核心；页面状态不能直接以平台回调内存为准。
- 前台和后台传输必须共享同一套服务端任务标识、分片编号、幂等键、完成确认和错误语义。
- 必须验证 HTTPS 证书和主机名，任何环境都不能通过关闭证书验证解决连接问题。
- 超时、重试条件、并发数、分片大小、平台传输实现和幂等有效期属于各功能协议方案，后续逐项确定。

#### 3.2.13 后端 API 基础规范

状态：已确认。

- App 和 Web 管理端通过 HTTPS REST API 访问 Go 后端。
- API 以 JSON 作为主要业务数据格式，字段统一使用 `snake_case`。
- API 主路径使用 `/api/v1` 版本前缀；不因单个兼容字段变化创建新版本。
- 使用 OpenAPI 3.1 描述并校验对外接口契约，生成的规范文件需要纳入版本控制和接口评审。
- 错误响应使用 RFC 9457 Problem Details，媒体类型为 `application/problem+json`，并增加稳定的业务错误码和请求追踪 ID。
- 时间使用 UTC 的 RFC 3339 字符串；对外 ID 使用不透明字符串，不允许客户端依赖数据库自增顺序。
- 列表接口默认使用游标分页，不使用会随数据插入而漂移的页码作为核心媒体列表分页方案。
- 可安全重试的创建或状态变更接口支持幂等键；具体适用接口和幂等有效期在功能方案中确定。
- MVP 不使用 GraphQL、gRPC 或 WebSocket。

#### 3.2.14 C++ 三端工程组织

状态：已确认。

- C++ 核心以 CMake 作为唯一构建描述，使用 Android NDK、iOS/Xcode 和 HarmonyOS NDK 对应工具链构建。
- Android 和 HarmonyOS 按目标 ABI 产出单个 `libmineg_core.so`；SQLite 和其他必要的 C/C++ 依赖优先静态链接进该产物，避免多个 C++ 运行时副本。
- iOS 产出同时包含真机和模拟器架构的 XCFramework，并静态链接进 App。
- `mineg_core.h` 是 JNI、Objective-C++ 和 Node-API 绑定层唯一允许依赖的公开 ABI 头文件。
- C ABI 只暴露固定宽度整数、字节缓冲区、不透明句柄和显式生命周期函数；不暴露 STL 类型、C++ 类、异常或实现依赖的结构体布局。
- 默认隐藏本地符号，只显式导出公开 C ABI；所有异常必须在 ABI 内部转换为稳定错误码。
- 三方依赖使用固定版本和完整性校验，不使用浮动分支或在构建时无校验下载最新版本。首版不引入 Conan 或 vcpkg，避免增加 HarmonyOS 交叉编译差异。
- 主机端单元测试纳入 CTest；C++ 代码使用统一格式化和静态检查，并在支持的测试目标启用 AddressSanitizer 和 UndefinedBehaviorSanitizer。
- Android JNI、iOS C/Objective-C++ 和 HarmonyOS Node-API 只保留薄绑定层，三端必须调用同一套 CMake 目标，不复制第二份核心源码。
- 在展开大规模 Android 业务实现前，必须在 Android 10、iOS 13 和 HarmonyOS 6.0 各完成一个最小接入验证：原生应用加载并调用 C++ 核心、SQLite 完成一次 Migration 和事务读写、通过 `TransportPort` 完成一次 HTTPS JSON 请求，并验证异步回调、取消和资源释放。
- 最小验证产物必须能够以发布模式安装和运行；HarmonyOS 需要在真实 HarmonyOS 6.0 环境验证 Node-API、共享库加载和三方依赖链接。
- Android 完整业务实现期间形成的公共行为必须写入版本化契约，不能只存在于 Kotlin 实现中。
- Android 参考实现完成后冻结首版公共契约，并使用相同的契约测试、状态机用例和故障轨迹验证 iOS 与 HarmonyOS 实现。
- 如果最小纵向验证失败，应先调整对应平台的构建或依赖接入方式；不能在未验证的情况下复制另一套业务数据核心。

### 3.3 功能实现技术方案

状态：开始逐项讨论。

后台扫描与上传、任务恢复、去重、媒体处理、权限控制和逻辑回收站等功能实现方案，在基础技术栈确认完成后再逐项讨论。

首项讨论账号注册、登录和后台审核的认证与授权方案。

#### 3.3.1 账号认证机制

状态：已确认，账号状态流转和接口细节继续讨论。

- 密码使用 Argon2id 生成不可逆哈希，每个密码使用独立随机盐；不保存明文密码，也不使用普通快速哈希直接保存密码。
- Argon2id 参数在目标 ECS 上测试后确定，不能低于采用时的安全基线。
- 移动端不使用 JWT，使用密码学安全的随机 Access Token 和可轮换 Refresh Token。
- PostgreSQL 只保存 Token 哈希、会话归属、创建时间、有效期、轮换关系和撤销状态，不保存原始 Token。
- Access Token 使用较短有效期；Refresh Token 每次成功刷新后轮换，旧 Token 立即失效。
- 移动端原始 Token 只保存在 Android Keystore、iOS Keychain 或 HarmonyOS Asset Store，不写入普通 C++ 业务数据库。
- 退出登录时撤销当前设备会话。
- Web 审核管理员使用服务端 Session Cookie，不把认证 Token 写入 `localStorage` 或 `sessionStorage`。
- 管理端 Cookie 使用 `Secure`、`HttpOnly`、`SameSite=Strict` 和受限作用域。
- 管理员身份和家庭成员身份执行独立授权；管理端审核权限不能访问成员私人媒体。
- 新注册账号初始为 `PENDING`，不能获得普通业务访问权限；审核通过为 `APPROVED` 后才能建立正式用户会话。
