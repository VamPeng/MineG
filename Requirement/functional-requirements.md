- 项目名称：MineG
- 文档版本：v0.2
- 文档状态：功能规划草案，待逐模块确认

- 产品需求基线：[MVP 产品需求基线 v1.1](./product-requirements.md)
- 技术需求基线：[MineG 技术需求 v0.3](./technical-requirements.md)

本文档把已经确认的产品范围拆分为可讨论、可设计、可开发和可验收的具体功能。本文不改变产品基线，不决定 API、数据库表、页面视觉稿或具体技术实现。

## 2. 规划原则

### 2.1 功能描述粒度

每个功能模块最终需要明确：

1. 使用角色和使用前提。
2. 功能入口和触发方式。
3. 正常业务流程。
4. 页面或任务需要展示的状态。
5. 失败、中断、重试和无数据情况。
6. 与隐私、权限和其他模块的联动规则。
7. 可独立验证的验收标准。

### 2.2 MVP 边界

- 系统只服务一个固定家庭。
- 移动端面向家庭成员；Web 管理端仅面向审核管理员。
- 自动备份媒体默认进入上传者的私人空间。
- 家庭共享必须由媒体所有者主动发起。
- 在线应用不物理删除 OSS 中的原文件。
- MVP 不增加搜索、筛选、评论、点赞、相册共享、密码找回、账号停用等产品基线之外的功能。
- 功能规划可以定义必要的默认排序、加载、错误反馈和空状态，但不能借此扩展新的业务能力。

## 3. 使用角色

| 角色 | 说明 | 核心权限 |
| --- | --- | --- |
| 访客 | 尚未登录的移动端使用者 | 注册、登录、查看审核状态说明 |
| 待审核成员 | 已注册但尚未审核通过 | 查看待审核状态、重新登录或刷新状态、退出当前账号 |
| 已审核成员 | 审核通过的家庭成员 | 管理本人资料、备份和浏览本人媒体、共享媒体、浏览家庭相册、管理本人回收站 |
| 审核管理员 | 内部 Web 管理端使用者 | 登录管理端、查看待审核账号、通过注册申请 |
| 运维清理人员 | 使用独立运维身份的人工操作者 | 生成永久清理预览、人工确认清理、查看清理结果和审计记录 |

审核管理员与运维清理人员是不同的权限边界。两者都不能通过管理功能浏览家庭成员的私人媒体内容。

## 4. 移动端功能结构

移动端 MVP 按以下一级功能区域规划：

1. 账号：注册、登录、待审核状态、退出登录。
2. 私人空间：浏览本人媒体、查看详情、下载、共享、删除。
3. 家庭相册：浏览全家已共享媒体、查看照片、播放视频。
4. 备份：授权引导、备份开关与网络设置、任务状态、失败处理。
5. 回收站：浏览本人已删除媒体、查看删除时间、恢复。
6. 个人页面：查看和修改本人昵称、头像，进入备份设置和账号操作。

此处只确定功能分区，不确定底部导航、页面层级和视觉布局。

## 6. 核心用户流程

### 6.1 新成员进入系统

1. 用户打开 App，选择注册。
2. 用户输入手机号和密码并提交。
3. 系统创建待审核账号。
4. 用户看到明确的待审核状态，不能进入普通业务页面。
5. 管理员在 Web 管理端查看待审核账号并通过申请。
6. 用户重新进入或刷新状态后登录。
7. 首次进入 App 时完成相册权限与备份设置引导。

### 6.2 首次自动备份

1. 已登录成员授权 App 访问设备相册。
2. App 说明默认仅 Wi-Fi 备份，并允许用户决定是否开启移动网络备份。
3. App 分批扫描可访问的历史媒体和相册归属。
4. 本地数据核心建立媒体索引和待上传任务。
5. 满足网络条件后开始上传。
6. 上传中断后保留任务状态，并在条件允许时继续。
7. 服务端确认完整上传后，媒体出现在用户私人空间。
8. 重复扫描和重试不产生重复云端媒体记录。

### 6.3 私人媒体共享

1. 用户从自己的私人空间打开一条正常状态的媒体。
2. 用户执行“共享到家庭相册”。
3. 系统确认共享成功后更新当前媒体状态。
4. 其他已审核成员可在家庭相册中看到该媒体。
5. 所有者取消共享后，该媒体立即从家庭相册消失，但仍在所有者私人空间中。

### 6.4 删除与恢复

1. 所有者从私人空间删除一条媒体。
2. 系统将媒体置为回收站状态并记录首次删除时间。
3. 媒体立即从私人空间正常列表和家庭相册隐藏。
4. 用户在回收站中恢复媒体。
5. 媒体重新回到私人空间正常列表。
6. 是否恢复删除前的共享状态需要先完成产品决策 D-007。

## 7. 具体功能需求

### F-01 注册、登录与会话

#### 目标

让固定家庭成员能够提交注册，在审核通过后安全登录，并在设备上维持可恢复的登录会话。

#### 功能要求

- 未登录状态提供“注册”和“登录”入口。
- 注册使用手机号、密码和确认密码，不发送短信验证码。
- 提交前检查必填、手机号格式和两次密码一致性。
- 服务端返回手机号已注册时，页面显示明确错误，不重复创建账号。
- 注册成功后进入待审核状态页，不能进入私人空间、家庭相册或备份功能。
- 登录使用手机号和密码。
- 待审核账号登录时进入待审核状态页，不建立普通成员业务会话。
- 审核通过的账号登录成功后进入 App 主功能。
- 密码错误、账号不存在、网络不可用和服务异常需要有可区分的反馈。
- App 启动时检查本机已有会话；会话可刷新时自动恢复登录。
- 会话失效且无法刷新时回到登录页，不继续展示需要在线权限的数据。
- 用户可以主动退出登录；退出后停止当前账号关联的后台任务并清除本机登录凭据。
- MVP 不提供忘记密码、修改密码、修改手机号或账号注销入口。

#### 待确认项

- D-001：手机号格式是否只接受中国大陆 11 位手机号。
- D-002：密码最小长度和复杂度。
- D-003：审核通过后，待审核页是自动轮询、用户手动刷新，还是重新登录后生效。
- D-004：已登录账号能否在同一设备切换到另一个账号，或必须先退出。

#### 验收要点

- 未审核账号无法访问普通成员接口和页面。
- 审核通过后可以用原手机号和密码登录。
- 错误密码不会泄露账号是否存在之外的敏感信息。
- 退出登录后，旧会话不能继续请求受保护资源。

### F-02 注册审核

#### 目标

让内部管理员以最小权限完成固定家庭新账号的人工准入。

#### 功能要求

- Web 管理端提供独立管理员登录页。
- 未登录管理员不能访问待审核列表。
- 待审核列表只展示完成审核所需的账号信息和注册时间。
- 管理员可以对一条待审核申请执行“通过”。
- 通过操作需要防止连续点击造成重复提交。
- 审核成功后，该申请从待审核列表移除。
- 如果账号已被其他操作通过，当前页面刷新为最新状态，不显示为失败的重复审核。
- 管理端不提供查看私人媒体、修改成员资料、重置密码、停用账号或删除账号的入口。
- 审核操作记录操作者、目标账号和操作时间。

#### 待确认项

- D-005：管理员账号的初始化方式和管理员数量。
- D-006：通过审核前是否需要二次确认。

#### 验收要点

- 普通家庭成员凭据不能登录管理端。
- 管理员无法通过页面或审核接口访问成员私人媒体。
- 同一账号只会从待审核状态成功流转到已审核状态一次。

### F-03 个人资料

#### 目标

让成员使用昵称和头像在家庭相册中被识别，同时不暴露完整手机号。

#### 功能要求

- 注册成功时，默认昵称为手机号后四位。
- 个人页面展示本人头像、昵称和脱敏后的账号标识。
- 用户可以修改自己的昵称。
- 用户可以选择并上传自己的头像。
- 保存成功后，App 内本人资料和家庭相册中的展示信息更新。
- 修改失败时保留用户当前输入，并提示重试。
- 其他家庭成员可看到昵称和头像，不能看到完整手机号。
- MVP 不提供查看或编辑其他成员资料的独立成员目录。

#### 待确认项

- D-008：昵称长度、允许字符和空白规则。
- D-009：头像支持格式、大小上限、裁剪方式及默认头像形式。

#### 验收要点

- 新用户首次进入时具有可展示的默认昵称。
- 修改资料不能改变账号手机号或访问权限。
- 所有家庭展示场景均不出现完整手机号。

### F-04 相册权限与备份设置

#### 目标

让用户理解并控制设备相册访问和网络使用方式，使自动备份具备合法、明确的启动条件。

#### 功能要求

- 首次需要扫描相册前展示权限用途说明，再发起系统权限请求。
- App 能区分完整授权、部分或受限授权、拒绝和系统限制。
- 完整授权时，备份全部可访问媒体。
- 部分或受限授权时，明确说明只会备份系统允许 App 访问的媒体，并提供前往系统设置的入口。
- 拒绝或系统限制时，不创建不可执行的扫描和上传任务。
- 用户在系统设置中修改权限后，App 返回前台时重新检查权限。
- 自动备份网络策略默认仅 Wi-Fi。
- 用户可以开启或关闭“允许移动网络备份”。
- 网络策略变化对尚未开始和正在等待的任务立即生效。
- 关闭移动网络备份时，不应粗暴取消已经由系统确认完成的上传结果。
- MVP 只在 App 内展示备份状态，不发送业务推送通知。

#### 待确认项

- D-010：自动备份是否提供总开关，以及首次授权后默认开启还是需要用户再次确认开启。
- D-011：部分相册权限下是否允许用户继续使用，或必须引导完整授权才能开启自动备份。

#### 验收要点

- 未获得可用相册权限时不会声称备份已开启。
- 默认网络策略不会在移动网络下启动新备份传输。
- 权限和网络设置变化后，页面状态与实际任务约束一致。

### F-05 设备媒体扫描与云端相册映射

#### 目标

可靠发现设备中的历史媒体和新增媒体，并保留足以组织云端相册的设备相册关系。

#### 功能要求

- 首次扫描覆盖系统授权范围内的全部历史媒体。
- 大型相册采用分批扫描，App 不因一次加载全部媒体而无响应。
- 后续运行监听媒体库变化，并在 App 启动或恢复时进行增量补扫。
- 变化事件只触发核对，不直接假定媒体最终状态。
- 对每条媒体记录平台本地标识、类型、格式、尺寸、时长、创建时间、修改时间和相册归属等必要信息。
- 一条媒体属于多个设备相册时保留多个归属关系。
- 云端相册使用设备提供的相册名称组织。
- 多设备出现同名相册时按同名同步原则展示，不增加特殊冲突解决规则。
- 设备本地删除媒体不删除已经完成的云端备份。
- 系统云相册中尚未下载、暂时不可读或资源失效的媒体进入明确的等待或失败状态，不误报为上传完成。
- 设备媒体被编辑或平台标识失效时重新核对是否需要生成新的备份任务。

#### 待确认项

- D-012：云端私人空间的默认浏览顺序。
- D-013：同一媒体属于多个设备相册时，私人空间的相册入口如何展示数量和归属。
- D-014：设备相册改名或媒体相册归属变化后，云端相册关系是否同步更新。
- D-015：编辑后的媒体按新媒体备份，还是更新已有媒体记录。

#### 验收要点

- 首次扫描结束后没有因分页遗漏授权范围内的历史媒体。
- 重复扫描不重复创建同一待上传任务。
- 设备媒体删除不会触发云端媒体删除。

### F-06 上传队列、续传与去重

#### 目标

在移动设备和不稳定网络环境中，把原始媒体可靠上传至私人对象存储，并避免同账号重复备份。

#### 功能要求

- 每条待备份媒体拥有可持久化的任务状态。
- 上传前确认账号、权限、网络策略和本地资源可读。
- 大文件使用分片上传，任务中断后可以从已确认的进度继续。
- App 进程被回收、设备重启或 App 升级后，能够重新关联或核对未完成任务。
- 临时错误采用受控重试；永久错误停止自动重试并显示原因类别。
- 上传完成必须经服务端和对象存储状态核对后才能标记为成功。
- 同一账号的重复扫描、重复点击、请求重试或同一设备重复上传不会生成重复云端媒体。
- 不同家庭成员上传相同内容时仍保留各自独立媒体记录。
- 私人原文件下载后写回系统相册形成的新条目，不能再次产生重复云端备份。
- 上传过程中不得为了预览或传输而降低原始媒体质量。
- 用户退出登录后，停止当前账号尚未完成的上传；重新登录同一账号后按规则恢复。

#### 待确认项

- D-016：同账号跨设备上传相同媒体是否需要去重。
- D-017：用户是否可以在 App 内暂停、继续或取消单个备份任务。
- D-018：永久失败任务的用户操作是“重试”还是同时提供“忽略”。
- D-019：上传队列的默认优先顺序。

#### 验收要点

- 网络中断后恢复不会重新上传已确认完成的全部内容。
- 同一媒体的并发或重复请求最终只形成一个有效媒体记录。
- 只有对象完整性确认成功的媒体才出现在私人空间正常列表。
- 原文件质量满足产品需求基线。

### F-07 备份状态与异常处理

#### 目标

让用户在 App 内知道备份是否正常、当前进度和需要采取的操作。

#### 功能要求

- 备份区域展示总状态，例如扫描中、等待 Wi-Fi、上传中、已完成、已暂停或存在失败。
- 展示对用户有意义的数量信息：待处理、进行中、已完成和失败。
- 上传中的媒体可以展示进度；无法获得精确进度时使用不误导的处理中状态。
- 权限不足、等待 Wi-Fi、网络不可用、本地资源不可读、云端资源待下载、磁盘空间不足、登录失效和服务异常需有不同提示。
- 可恢复问题提供明确操作，例如前往设置、连接 Wi-Fi、重新登录或重试。
- App 被系统限制后台执行时，不承诺持续运行，回到前台后继续核对任务。
- 备份完成状态以持久化任务和服务端结果为准，不只依赖页面内存状态。
- MVP 不提供按日期、文件名或媒体类型筛选失败任务。

#### 待确认项

- D-020：备份状态展示聚合到什么层级，是否需要单独的任务列表。
- D-021：完成数量是本次任务数量、设备累计数量，还是云端累计数量。

#### 验收要点

- 用户能够分辨“没有待备份媒体”和“备份因条件不满足而没有运行”。
- App 重启后仍能恢复正确的任务数量和状态。
- 页面不会在服务端尚未确认时显示全部备份完成。

### F-08 私人空间浏览与媒体详情

#### 目标

让成员只浏览自己的云端媒体，并进入查看、下载、共享和删除操作。

#### 功能要求

- 私人空间只返回当前登录成员拥有且未进入回收站的媒体。
- 支持按云端相册进入媒体列表，但不提供搜索和筛选。
- 媒体列表使用游标加载，支持空状态、首次加载、继续加载失败和重试。
- 网格使用缩略图或低分辨率预览，不下载原文件作为列表图片。
- 照片支持全屏查看。
- GIF 保持动态展示。
- 视频支持在线播放、暂停、拖动和停止。
- 实况照片使用平台支持的展示方式；降级规则需要在媒体兼容方案中确认。
- 媒体详情展示执行下载、共享、取消共享和删除所需的当前状态。
- 临时访问地址过期后重新鉴权获取，不把永久地址保存在页面中。
- 预览生成或格式不兼容不能损坏或替换原文件。

#### 待确认项

- D-022：媒体详情需要展示的元数据范围。
- D-023：照片、视频、GIF、实况照片的兼容和降级清单。
- D-024：缩略图暂不可用时的占位和重试行为。

#### 验收要点

- 成员不能通过列表、详情或直接构造请求访问其他成员未共享媒体。
- 大量媒体采用连续加载，不一次性载入全部数据。
- 预览失败不影响原文件仍被安全保存。

### F-09 私人原文件下载

#### 目标

让媒体所有者把私人空间中的原文件保存回设备系统相册。

#### 功能要求

- 下载入口只出现在本人私人空间媒体中。
- 下载前由后端校验当前用户是媒体所有者。
- App 获取短期访问授权并下载原文件。
- 下载完成后按平台要求写入系统相册。
- 只有系统相册保存成功后，页面才显示下载完成。
- 系统权限拒绝、网络中断、磁盘不足、访问授权过期和保存失败需要明确反馈。
- 失败后可以重试，不调用系统分享面板作为替代方案。
- 家庭相册中不提供下载、保存、导出或二次分享入口。
- 下载生成的本地媒体不得被自动备份为重复云端媒体。

#### 待确认项

- D-025：设备系统相册已存在同一下载媒体时，是跳过、再次保存，还是提示用户。

#### 验收要点

- 非所有者无法获得私人原文件下载授权。
- 保存后的媒体保持产品定义的原文件质量和动态资源组成。
- 家庭相册页面和接口不存在下载能力。

### F-10 单媒体共享与取消共享

#### 目标

让媒体所有者把单条私人媒体主动共享给全家查看，并随时撤销。

#### 功能要求

- 只有媒体所有者可以共享或取消共享。
- 只有正常状态且已完成上传的媒体可以共享。
- MVP 每次操作一条媒体，不提供批量共享或整个相册共享。
- 共享操作成功后，私人媒体详情展示已共享状态。
- 重复共享请求保持幂等，不产生多条家庭相册记录。
- 取消共享成功后，媒体立即从家庭相册的后续查询和访问授权中消失。
- 重复取消共享保持幂等。
- 媒体进入回收站时自动变为不可共享，并从家庭相册隐藏。
- 分享和取消分享失败时保留服务端确认的原状态，不只在本地乐观修改。

#### 待确认项

- D-026：共享前是否需要确认提示。
- D-027：取消共享前是否需要确认提示。

#### 验收要点

- 非所有者不能改变共享状态。
- 取消共享或删除后，原家庭访问地址即使尚未自然过期，也不能绕过业务授权继续刷新访问。
- 共享不改变媒体所有权和私人下载权限。

### F-11 家庭相册浏览与播放

#### 目标

让所有已审核成员浏览家庭成员主动共享的媒体，但不提供原文件带走能力。

#### 功能要求

- 家庭相册只展示当前仍为共享状态且未进入回收站的媒体。
- 列表展示共享者的昵称和头像，不展示完整手机号。
- 列表采用游标加载，不提供搜索和筛选。
- 支持照片全屏查看、GIF 动态展示和视频在线播放。
- 页面不提供下载、保存、导出和系统分享入口。
- 家庭查看使用适合展示或播放的短期授权，不能复用私人下载权限。
- 媒体被取消共享或删除后，刷新列表和详情时立即不可见。
- 正在查看的媒体被取消共享时，下一次需要服务端授权的请求必须失败，并退出不可继续访问的详情。
- 明确承认系统无法绝对阻止截屏、录屏或提取已经显示的数据，不在 UI 中作绝对安全承诺。

#### 待确认项

- D-028：家庭相册默认排序。
- D-029：家庭相册是否展示共享时间。

#### 验收要点

- 未共享媒体不会出现在家庭相册或家庭访问接口。
- 家庭相册的任何入口都不能获得私人原文件下载授权。
- 取消共享和删除状态能及时影响列表及后续访问。

### F-12 逻辑回收站与恢复

#### 目标

让成员安全删除和恢复自己的云端媒体，不由在线 App 物理删除原文件。

#### 功能要求

- 只有媒体所有者可以把媒体移入回收站。
- 删除操作执行前给出明确确认，说明不会删除设备本地媒体。
- 删除成功时记录首次进入回收站的准确时间 `trashed_at`。
- 已在回收站的媒体不能因重复请求更新 `trashed_at`。
- 回收站只展示当前用户自己的已删除媒体。
- 回收站媒体从私人空间正常列表和家庭相册隐藏。
- 回收站展示进入时间或已放置时长，不展示虚构的自动到期时间。
- 用户可以恢复尚未被人工永久清理的媒体。
- 恢复成功后媒体重新出现在私人空间。
- 被人工永久清理的媒体不能恢复。
- 在线 App 不提供永久删除按钮，不具有 OSS 永久删除权限。
- App 删除云端媒体时不得调用系统能力删除设备本地媒体。

#### 待确认项

- D-007：恢复媒体时是否恢复删除前的家庭共享状态。建议 MVP 默认不自动恢复共享，由所有者重新共享，以减少意外暴露。
- D-030：回收站默认排序。

#### 验收要点

- 删除和恢复是数据库业务状态变化，不移动或复制 OSS 原文件。
- 重复删除不改变首次 `trashed_at`。
- 删除后所有正常浏览与共享路径立即不可见。
- App 中没有永久删除能力。

### F-13 人工永久清理

#### 目标

使用与在线应用隔离的运维权限，对回收站媒体进行可预览、可确认、可审计的永久清理。

#### 功能要求

- 清理工具不属于移动端或首版 Web 审核管理端。
- 操作者使用独立运维身份和 OSS 删除权限。
- 支持按进入回收站时间、时间范围、用户和媒体类型组合筛选。
- 执行删除前生成不可歧义的待删除清单。
- 预览至少展示筛选范围、媒体数量、对象数量和总容量。
- 清单需要区分一条逻辑媒体对应多个底层资源的情况。
- 未经人工确认不能执行 OSS 删除。
- 清理执行后核对每个对象结果，不因部分失败把整批标记为成功。
- 成功清理的媒体记录实际清理时间 `purged_at`。
- 保留操作者、筛选条件、清单标识、确认时间、执行结果和失败明细。
- 重复执行同一清理任务不得误删清单之外的对象。
- 清理工具不能删除正常状态或已恢复媒体的对象；执行前必须再次核对当前业务状态。

#### 待确认项

- D-031：清理工具采用命令行、受限内部页面还是两阶段脚本。
- D-032：清理清单的保存格式、审批人和审计记录保留期限。

#### 验收要点

- 在线应用身份无法执行 OSS 永久删除。
- 预览与确认之间已恢复的媒体不会被删除。
- 部分失败可以准确重试且保留完整审计记录。

## 8. 状态规划

### 8.1 账号状态

```text
未注册 -> PENDING（待审核） -> APPROVED（已审核）
```

- MVP 没有拒绝、停用、删除和重新申请状态。
- `PENDING` 只能访问注册结果和审核状态所需能力。
- `APPROVED` 才能建立普通成员业务会话。

### 8.2 客户端备份任务状态

建议功能层统一使用以下语义，具体字段和状态机在技术方案中确定：

```text
发现 -> 等待条件 -> 准备资源 -> 上传中 -> 服务端确认 -> 完成
                  |          |
                  v          v
                可重试失败 / 永久失败
```

补充状态规则：

- 等待条件应能区分权限、网络、系统调度和本地资源原因。
- 暂停、取消和忽略是否开放给用户，由 D-017 和 D-018 决定。
- “完成”必须是终态核对结果，不能只代表客户端字节发送结束。

### 8.3 媒体业务状态

媒体所有权、备份状态、共享状态和删除状态是不同维度，不能合并成一个含义模糊的状态：

- 所有权：固定归属一个上传账号。
- 备份：未完成、完成或失败等任务状态。
- 共享：未共享或已共享。
- 删除：正常、回收站、已永久清理。

约束：

- 只有备份完成且删除状态正常的媒体可以共享。
- 进入回收站后强制不可在家庭相册访问。
- 已永久清理后不可下载、共享或恢复。

## 9. 跨功能规则

### 9.1 隐私与授权

- 每次读取媒体列表、详情、播放地址、下载地址或修改状态都由服务端依据当前账号和媒体状态授权。
- 客户端隐藏按钮不能代替服务端权限校验。
- 短期地址不能成为永久访问凭据。
- 日志、错误提示和管理端页面不能输出完整访问令牌、OSS 临时凭据或不必要的完整手机号。

### 9.2 时间与排序

- 服务端业务时间统一记录为 UTC，客户端按设备时区展示。
- 默认排序属于浏览功能的必要行为，不视为产品基线中禁止的“按日期筛选”。
- 私人空间、家庭相册和回收站的默认排序分别通过 D-012、D-028 和 D-030 确认。

### 9.3 空状态与失败状态

每个列表或任务页面至少覆盖：

- 首次加载中。
- 没有数据。
- 加载成功且有数据。
- 首次加载失败，可重试。
- 继续加载失败，保留已展示数据并可重试。
- 登录或权限失效，停止当前操作并引导恢复。

### 9.4 幂等与重复操作

注册提交、审核通过、上传任务创建、上传完成确认、共享、取消共享、删除和恢复等可能被重试的操作，需要在功能方案和 API 方案中明确幂等语义。

### 9.5 原文件与预览

- 原文件是永久保存对象，缩略图、封面和播放预览是可重新生成的派生资源。
- 派生资源失败不能改变原文件成功状态。
- 预览处理不能覆盖原文件。
- 一条逻辑媒体包含多个底层资源时，下载、恢复和人工清理必须按完整资源集合处理。

## 10. 分阶段落地顺序

### 阶段 0：三端共享核心最小接入验证

- 建立平台无关的命令、查询、事件、错误和资源生命周期契约草案。
- Android/Kotlin 通过 JNI 调用 C++17 数据核心。
- iOS/Swift 通过 C/Objective-C++ 薄封装调用同一数据核心。
- HarmonyOS/ArkTS 通过 Node-API 调用同一数据核心。
- SQLite 完成一次 Migration 和事务读写。
- 通过统一 `TransportPort` 完成一次 HTTPS JSON 请求。
- 验证异步回调、取消、资源释放以及一段大文件的流式读取和校验。
- Android、iOS、HarmonyOS 在最低目标系统对应环境完成发布模式安装运行。

阶段验收：同一份 C++ 核心源码和公共契约可以被三端原生应用加载调用，不需要复制第二套数据核心。完成后再扩大 Android 业务代码规模。

### 阶段 1：Android 账号准入闭环（含 Web 审核）

- F-01 注册、登录与会话。
- F-02 注册审核。
- F-03 个人资料基础能力。

阶段验收：Android 新成员可以注册，经管理员通过后登录，并看到不暴露完整手机号的本人资料。

### 阶段 2：Android 单条媒体备份纵向闭环

- F-04 相册权限与网络设置。
- F-05 发现一条设备媒体。
- F-06 上传原文件并完成服务端确认。
- F-07 展示准确任务状态。
- F-08 在私人空间查看该媒体。

阶段验收：Android 完成一条代表性照片的发现、上传、确认和私人查看；业务状态必须由 C++ 数据核心持久化，Android 平台对象不得进入公共模型。

### 阶段 3：Android 完整自动备份

- 历史媒体分页扫描。
- 新增媒体增量补扫。
- 多媒体类型和多资源媒体。
- 分片上传、断点续传、重试和去重。
- 后台恢复和异常状态。
- 云端相册映射。

阶段验收：大规模历史相册和持续新增媒体能够在系统允许范围内可靠完成备份。

### 阶段 4：Android 私人使用闭环

- F-08 完整浏览与播放。
- F-09 私人原文件下载。
- F-12 删除、回收站和恢复。

阶段验收：用户可以完整管理自己的云端媒体，且设备与云端删除互不影响。

### 阶段 5：Android 家庭共享闭环

- F-10 共享与取消共享。
- F-11 家庭相册浏览与播放。
- 删除、恢复和共享状态联动。

阶段验收：共享媒体对全家可见，取消共享或删除后立即不可见，且家庭成员不能下载原文件。

### 阶段 6：公共契约 v1 冻结

- 汇总 Android 参考实现中已经验证的命令、查询、事件、错误和资源生命周期。
- 把平台无关行为写入版本化公共契约，不把 MediaStore URI、WorkManager 对象等 Android 机制写入契约。
- 固化数据模型、SQLite Migration、任务状态机、重试、幂等、去重和服务端确认规则。
- 建立可在三端重复执行的契约测试、状态机测试和故障轨迹。

阶段验收：公共行为不依赖阅读 Kotlin 实现即可完整理解和验证；Android 通过首版完整契约测试。

### 阶段 7：iOS 原生实现

- 使用 Swift 原生实现 F-01 至 F-12 的页面与平台能力。
- 使用 PhotoKit、系统安全存储、后台传输和生命周期能力实现对应平台适配器。
- 复用同一 C++ 数据核心、数据库规则和公共契约。

阶段验收：iOS 通过与 Android 相同的业务契约、状态机和故障测试，并完成完整 MVP 用户闭环。

### 阶段 8：HarmonyOS 原生实现

- 使用 ArkTS 和 ArkUI 原生实现 F-01 至 F-12 的页面与平台能力。
- 使用 HarmonyOS 媒体库、安全存储、后台任务和系统传输能力实现对应平台适配器。
- 复用同一 C++ 数据核心、数据库规则和公共契约。

阶段验收：HarmonyOS 通过与 Android、iOS 相同的业务契约、状态机和故障测试，并完成完整 MVP 用户闭环。

### 阶段 9：运维与三端发布验收

- F-13 人工永久清理。
- 权限越权测试。
- 任务恢复和故障测试。
- 原文件质量与媒体兼容验收。
- 日志、审计、监控、备份和部署检查。
- Android、iOS 和 HarmonyOS 最低目标系统及当前发布目标系统的安装、升级和回归验证。

1. F-01 注册、登录与会话，同时确认 D-001 至 D-004。
2. F-02 注册审核，同时确认 D-005 至 D-006。
3. F-03 个人资料。
4. F-04 相册权限与备份设置。
5. F-05 至 F-07 自动备份主链路。
6. F-08 至 F-09 私人浏览和下载。
7. F-10 至 F-11 家庭共享。
8. F-12 回收站。
9. F-13 人工永久清理。

每个模块确认后，再将对应结论同步到页面需求、接口契约、状态机、数据模型和测试用例中。
