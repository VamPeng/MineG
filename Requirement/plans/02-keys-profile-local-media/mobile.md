# 阶段 02 移动端执行计划：密钥、资料、权限与本地相册

> 2026-07-30 数据主权修订：本阶段历史验收保持不变；资料/头像/key grant 的接口编排和本地索引必须由 C++ Core 负责，平台只执行安全存储、MediaSource 和传输 Effect。批次 D 的扫描采用前台从头执行，不使用系统调度或断点恢复，详见[批次 D 需求](./batch-d-requirements.md)。

## 目标与范围

对应 M2，并补齐 M1 的资料编辑。Android 完成 F-03～F-06：家庭 key grant、资料、相册权限、备份设置、媒体扫描和本地相册真实索引。

## 实施任务

- 实现家庭密钥首成员 bootstrap 与现有成员 key grant；密钥只在安全存储/受控内存中解封。
- 实现昵称编辑、头像选择与方形裁剪、格式/大小校验和上传结果展示。
- 在契约中登记权限状态、备份设置、相册/媒体模型、扫描命令、Port 方法、页面 ID 与操作。
- Android 统一权限说明页；仅完整授权启动前台扫描，部分/受限/拒绝均不读取媒体，权限满足后从第一页开始。
- SQLite 持久化默认关闭自动备份、默认禁止移动网络的设备级设置，提供开始备份按钮和全局开关。
- 使用 MediaStore 按稳定平台 ID 分页扫描媒体与相册，记录修改版本、多相册关系和 MineG 下载回执；批次 D 每次从头扫描，增量与后台扫描留到阶段 04。
- 实现本地相册分页、两列相册封面卡片和单相册三列媒体网格；扫描状态来自真实本地索引，不伪造上传进度。

## 测试重点

- 完整/部分/拒绝/撤销权限，空相册、相册改名、多相册归属、编辑后媒体和 10 万条索引分页。
- 正常重启后设置和最后完成的索引仍可读取；扫描游标不恢复，下次扫描从第一页开始。切换账号前必须退出并隔离本地数据。
- key grant 重复执行不会产生不同家庭密钥或泄露密钥内容。

## 完成门槛

- 获批账号完成 envelope 后进入主导航，可修改资料并浏览真实本地相册。
- 权限不足时不读取媒体；完整权限后可前台分页扫描且不一次载入全部索引。
- F-03～F-06 的公共契约与 Android 语义测试通过并转为 `FROZEN`。
