# 阶段 02 后端执行计划：家庭密钥授权与个人资料

## 目标与范围

对应 B2。完成家庭密钥 envelope 协调、首成员 bootstrap、新成员 key grant，以及本人资料和头像元数据服务。

## 实施任务

- 新增固定家庭记录、`family_key_envelopes`、key grant 任务和用户资料/头像元数据 migration。
- 实现首成员一次性原子 bootstrap；服务端只验证 envelope 元数据和签名关系，不接触家庭密钥明文。
- 实现待处理 key grant 查询与完成接口，保证重复提交幂等、并发领取安全、错误 envelope 失败关闭。
- envelope 完整后事务性把用户对外状态置为 `APPROVED`；现有成员离线时新成员继续保持待审核。
- 实现 `GET /me`、资料更新、头像上传授权与短期读取；昵称和头像格式/大小按功能基线校验。
- 补齐 key grant 积压、失败、完成时延指标和审计，但不得记录 envelope 内容。

## 接口与数据交接

- 冻结 `/me`、key bundle、key grant、资料和头像接口及错误码。
- 向阶段 03 提供可用的用户主密钥包、家庭 envelope 元数据和账号私有去重键封装前提。
- 头像对象与媒体对象使用分离前缀和用途授权。

## 验证与完成门槛

- 首成员、后续成员、离线等待、重复 grant、错误成员公钥和并发完成均有集成测试。
- 管理员、其他用户和普通数据库读取均不能得到明文密钥。
- Android 获批用户只有在 envelope 就绪后进入 App，并能真实读取/修改本人资料和头像。

## 不在本阶段

媒体上传、家庭媒体访问和管理端资料页面。
