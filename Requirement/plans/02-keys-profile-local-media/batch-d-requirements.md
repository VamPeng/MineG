# 批次 D 需求：前台本地相册索引与备份偏好

## 1. 目标

批次 D 只完成两件事：

1. 用户在 App 前台授权访问相册后，MineG 读取本机媒体并生成可分页浏览的本地索引；
2. 保存“自动备份”和“允许移动网络”两个备份偏好，供后续阶段 04 的真实备份队列使用。

本批次不上传媒体，也不执行后台任务。App 执行扫描时若进程结束，下次进入页面直接从第一页重新扫描，不恢复上一次执行步骤。

### 1.1 与最终产品需求的关系

本文件定义的是 M3-D 数据主权迁移中的阶段性交付，不修改 F-05/F-06 的最终产品目标。用户开启自动备份后的媒体发现、按网络条件上传、增量扫描和关闭后停止新工作，仍由阶段 04 完整队列实现。批次 D 只先交付可复用的本地索引和设置真相，页面需要明确此时尚未发生云端备份。

## 2. 用户场景

### D-US-01：首次建立本地索引

用户授予完整相册权限后，若当前账号还没有完成索引，App 在进入本地相册或备份首页时前台读取相册与媒体。读取完成后，页面展示真实相册、媒体数量和缩略图。

### D-US-02：刷新本地索引

已有完整索引时，再次进入页面只读取现有索引；用户主动点击刷新才重新从第一页扫描。扫描完成后，一次性切换到新索引；扫描期间已有的完整索引仍可继续展示。

### D-US-03：权限不足

相册权限不是 `FULL` 时，不开始扫描，页面展示权限说明和授权入口。权限恢复为 `FULL` 后重新发起一次全新扫描。

### D-US-04：修改备份偏好

用户可以开启或关闭自动备份、允许或禁止移动网络。修改后立即保存并在再次启动 App 时读取相同值。

这两个开关在批次 D 只代表偏好，不触发扫描、上传、系统唤醒或后台工作；页面不得用它们伪造正在备份或备份完成状态。

## 3. 功能需求

| ID | 需求 |
| --- | --- |
| D-REQ-001 | 只有完整相册权限可以开始扫描；其他权限状态统一返回“需要完整权限”。 |
| D-REQ-002 | 扫描只在 App 前台由页面动作触发，不注册 WorkManager 或其他系统后台任务。 |
| D-REQ-003 | 每次扫描都从空游标开始；不读取或恢复上一次扫描的游标、步骤和内存状态。 |
| D-REQ-004 | MediaSource 每页最多返回 500 条，Core 逐页处理，不能把全部媒体一次载入内存。 |
| D-REQ-005 | 索引保存媒体基本信息、相册基本信息和媒体—相册关系，支持相册与媒体分页查询。 |
| D-REQ-006 | 新索引完整生成后才替换当前可见索引；未完成的候选索引不能成为页面数据源。 |
| D-REQ-007 | 再次完整扫描应反映新增、编辑、删除、相册改名和多相册归属变化。 |
| D-REQ-008 | 本地索引按账号隔离；退出或切换账号后不得查询到其他账号的索引。 |
| D-REQ-009 | 备份偏好按账号和 App 安装实例保存，默认自动备份关闭、移动网络关闭。 |
| D-REQ-010 | 本地相册浏览不依赖自动备份开关；即使自动备份关闭，用户仍可主动建立和刷新本地索引。 |
| D-REQ-011 | UI 只显示 Core 已确认的索引和设置，不在 ViewModel 中维护第二份业务真相。 |
| D-REQ-012 | 没有完整索引时首次进入自动扫描；已有完整索引时进入页面只查询，只有用户刷新才重新扫描。 |

## 4. 理想执行流程

```text
首次无索引进入本地相册/用户点击刷新
  → Core 请求当前相册权限
  → Android 返回权限结果
  → FULL：Core 创建本次前台扫描的临时内存上下文
  → Core 逐页请求 Android MediaStore 数据（每页 ≤ 500）
  → Core 将每页写入新的候选索引
  → 最后一页完成后，Core 原子切换当前索引
  → UI 重新查询相册和媒体分页
```

备份设置流程：

```text
用户切换开关
  → Core 校验并写入 SQLite
  → Core 发布设置已变化事件
  → UI 读取并展示新设置
```

## 5. 必须保留的最小保护

本批次按理想流程设计，不建设通用重试、恢复或后台调度框架，只保留以下无法靠“盲目继续执行”保证正确性的保护：

- SQLite 每批写入和最终索引切换必须使用事务，避免页面读取半批数据；
- 当前可见索引只能指向已完成的一代，避免进程结束后展示半成品；
- 大数据量必须分页，避免 10 万条媒体导致内存溢出；
- 权限和账号隔离必须在读取前校验，避免读取越权数据。

若 App 在扫描中结束，不恢复该次扫描。下次扫描从头开始，并清理没有成为当前索引的候选数据。

## 6. 非本批次范围

- WorkManager、系统后台唤醒和后台扫描；
- 媒体加密、上传、备份队列和上传进度；
- 断点续扫、operation 恢复、持久化执行游标；
- 网络条件门禁、Wi-Fi/移动网络切换执行；
- 自动重试、退避、失败任务恢复和设备重启后续跑；
- 单媒体上传、分片、STS 和服务端完成确认。

上述能力统一留到阶段 04，在真实备份队列存在时设计。

## 7. 验收标准

- 完整权限下可完成空相册、500 条以上和 10 万条媒体的分页扫描；
- 扫描结果正确反映新增、编辑、删除、相册改名和多相册关系；
- 非完整权限不读取 MediaStore，也不产生候选索引；
- 自动备份关闭时仍可主动刷新和浏览本地相册；
- 两个备份偏好在 App 正常重启后保持，且不同账号、不同安装实例互不覆盖；
- 扫描中终止进程后，旧的完整索引保持可用；下次扫描从空游标开始，不恢复旧步骤；
- 代码和依赖中不存在批次 D 专用 Worker、`BackgroundSchedulerEffect` 或 WorkManager 调度调用；
- 页面展示的数据均可追溯到 Core Query/Event，不以 ViewModel 本地修改冒充成功。
