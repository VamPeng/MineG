# 阶段 04 移动端执行计划：Android 完整队列与备份状态

> 统一设计与验收口径见[阶段 04 技术方案](./technical-design.md)；公共契约基线见 [`stage04-v1`](../../../Mobile/contracts/stage04-v1.json)。

## 目标与范围

对应 M4。将单媒体上传扩展为历史/增量扫描、网络约束、并发、重试和崩溃恢复完整闭环，冻结 F-08 队列契约。

## 实施任务

- 先登记 `stage04-v1` 的 Command、Query、Event、状态、错误和 Effect action；Android 验收前保持 `BASELINED`。
- 使用顺序 migration 在 C++ SQLite 建立持久扫描、任务、资源、分片、尝试次数、重试时间、服务器会话、租约与完成确认状态；不得复用旧密文任务表。
- 在 C++ Core 实现历史/增量扫描及任务条件迁移：权限/设置/网络门禁、准备、创建会话、上传、服务端确认、完成、可重试失败和永久失败。
- 历史发现和队列默认按拍摄时间从新到旧；最多 2 个并发媒体、每媒体 2 个并发分片，并支持 `Retry-After` 与 5 秒～15 分钟抖动退避。
- Android WorkManager 只负责获得执行机会，业务状态始终以 C++ SQLite 为准；重启、进程回收和网络切换后恢复。
- Android 不得解析上传业务 DTO、决定分片重试或维护队列镜像；Worker 只恢复 Core operation、执行 PlatformEffect 并回传结果。
- 实现 MediaStore 变化通知、历史/增量扫描、Wi-Fi/移动网络切换、全局自动备份开关、主动重试和会话/授权过期刷新。
- 备份页展示真实扫描、上传、等待 Wi-Fi、离线、空间不足、服务异常、会话过期和完成状态；百分比代表当前资源。
- 生成 MineG 写回回执并在扫描时去重，避免下载保存内容再次备份。

`ENCRYPTING`、Media Key、密文临时文件和加密清单不得进入新主链；Stage03-v2 的单媒体入口在批量队列稳定后改为复用同一持久任务，而不是保留第二套内存上传状态机。

## 测试重点

- 10 万条索引分页、1 GiB 视频、进程强杀、设备重启、断网、切网、STS 过期、分片损坏和完成响应丢失。
- SQLite 状态机属性测试保证无非法跃迁、重复副作用和永久卡死。
- 自动备份关闭后不启动新任务，已有外部请求安全收尾；重新开启后恢复。
- 静态扫描保证 Kotlin 生产代码没有业务 API 路径、上传 DTO 解析、任务数据库和重试状态机。

## 完成门槛

- 当前设备无待服务端确认任务时才显示完成，所有异常有真实重试路径。
- 同账号重复扫描、队列重放和跨设备去重不产生重复云端媒体。
- 强杀、设备重启和授权重签后只补传当前服务端会话未确认的分片。
- F-08 状态、事件、错误与备份页交互契约通过并转为 `FROZEN`。
