# 阶段 04 后端执行计划：可恢复上传与私人列表支撑

> 统一设计、API 增量和故障矩阵见[阶段 04 技术方案](./technical-design.md)。

## 目标与范围

对应 B3/B4。把阶段 03 的单媒体能力加固为可承载完整客户端队列的幂等服务，并提供备份完成后所需的本人媒体分页查询基础。

## 实施任务

- 完善上传会话状态、有效期、精确已确认分片集合、授权代次、分片幂等、并发完成、去重命中和客户端断点查询。
- 为大量历史媒体建立适当索引、条件更新和游标分页，避免 offset 随数据增长退化。
- 增加规范 `GET /api/v1/private/media`，并为现有 `GET /api/v1/media` 保留一个兼容周期；只返回已完成、未删除、本人所有媒体摘要，不签发对象地址。
- 在创建会话中兼容接收稳定客户端相册 ID 与名称；正常完成和同账号去重命中都幂等补齐媒体相册关系。
- 为 STS 过期、OSS 限流、数据库连接耗尽、空间配额和完成核对失败定义稳定可重试性错误及 `Retry-After`。
- 建立上传成功率、会话积压、分片重试、STS/OSS 错误、完成时延与去重命中指标。
- 定义过期未完成 multipart 的安全清理候选和受限 dry-run；不得影响已完成媒体对象。

继续沿用 Stage03-v2 的每媒体上传接口，不增加批量上传 endpoint、服务端任务队列或后台消费者。媒体保持 `MEDIA_ORIGINAL`，不写旧密文字段和 key envelope。

## 容量与可靠性验证

- 使用批量会话、乱序分片、网络切换、完成响应丢失、重复请求和并发同内容压测状态收敛。
- 验证游标 HMAC 绑定用户、过滤和 `(captured_at DESC, id DESC)` 排序，不能跨账号或跨过滤条件复用。
- 隔离 OSS 故障时数据库不误标完成；数据库提交失败时客户端可安全重试。
- 验证会话续签保留精确确认集合，multipart 重建时明确重置确认集合且不会误报完成。

## 完成门槛

- Android 完整历史/增量队列可持续创建会话并恢复，不需要人工修改服务端状态。
- 私人列表只出现服务端已确认媒体，账号隔离和游标稳定性测试通过。
- 告警可区分客户端网络、STS、OSS、数据库与清单核对失败。
- 两设备同账号上传相同内容只产生一个有效媒体；不同账号永远不复用媒体或对象。

## 不在本阶段

私人详情/原文件保存、分享、删除与恢复；缩略图/预览访问授权；管理端媒体或任务监控。
