# 阶段 03 移动端执行计划：Android 单媒体加密备份

> 2026-07-30 数据主权修订：C++ 持久化上传状态但由 Kotlin 决定网络步骤不满足共享状态机要求。本阶段转为 `FROZEN` 前必须把创建会话、分片、ETag 上报、服务端确认、去重与失败迁移编排到 C++ Core，平台 `TransportPort` 只执行 Effect。

## 目标与范围

对应 M3。用一条真实媒体验证从 MediaStore 到 C++ 加密核心、后端、OSS 再到服务端确认的完整链路，冻结 F-07 和单媒体 F-08 契约。

## 实施任务

- 在 C++ 核心实现随机 Media Key、资源 KDF、4 MiB XChaCha20-Poly1305 分块、Nonce/AAD 规则和认证加密清单。
- 实现账号私有 `dedupe_key` 的规范化资源摘要 HMAC，确保服务端不能跨账号比较内容。
- 由平台适配器生成缩略图、视频封面和可用预览；每个派生资源使用独立 Resource Key 并加密。
- 在 C++ Core 实现单媒体上传状态机：创建会话、取得 STS、产生分片传输 Effect、消费 ETag/摘要、提交完成和处理去重命中；平台只执行传输与文件原语。
- 所有状态先写 SQLite 再触发外部副作用；进程被杀后可从最后确认分片恢复。
- 覆盖照片、视频、GIF、Live/动态资源代表样本；平台无法预览时上传原文件密文并记录降级能力。
- 在契约登记上传命令、进度事件、资源图、错误、取消与释放规则。

## 安全与测试

- 使用固定测试向量验证三端未来可互解；密文篡改、块重排、截断、清单错配必须失败关闭。
- 断网、STS 过期、分片重试、完成响应丢失和重复扫描后不得产生重复媒体。
- 大资源流式处理，不在普通缓存留下第二份长期明文。

## 完成门槛

- 至少一张真实照片及各代表性资源在隔离 OSS 完成加密直传和服务端确认。
- 服务确认前不进入私人空间；确认后本地任务为 `COMPLETED`。
- F-07 与单媒体上传公共契约测试通过并转为 `FROZEN`。
