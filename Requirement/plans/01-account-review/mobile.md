# 阶段 01 移动端执行计划：Android 账号准入

## 目标与范围

对应 M1，在 Android 完成 F-01～F-03 的账号准入主路径，并先登记、后冻结三端公共契约。

## 实施任务

- 在契约中登记账号、会话、资料基础模型，注册/登录/刷新/退出命令，错误码、页面 ID、操作和状态。
- 实现登录、注册、协议勾选、手机号/密码校验、凭据错误、网络错误和重复手机号状态。
- 注册时在客户端生成用户密钥材料，只上传公钥和加密 key bundle；明文私钥不离开客户端。
- 使用 Android Keystore 保存原始 Token 和设备包装密钥；SQLite 只存非敏感会话状态。
- 实现待审核页面：可见时 10 秒轮询、手动刷新、回前台刷新；envelope 未就绪时仍保持待审核。
- 实现会话恢复、Refresh Token 轮换、重放/过期后的安全退出及当前账号退出确认。
- 建立个人中心与资料展示的最小真实入口，资料编辑在阶段 02 完成。

## 联调与测试

- 对接阶段 01 后端和管理端，不使用模拟审核结果。
- 覆盖表单错误、协议未勾选、重复提交、网络中断、进程回收、Token 过期和账号切换限制。
- 验证 Token/私钥不出现在日志、崩溃信息、SQLite 和截图测试数据中。

## 完成门槛

- Android 可完成注册—管理员批准—等待 key grant 状态—登录—会话恢复—退出闭环。
- F-01～F-03 已实现部分的公共方法、错误和 UI 语义测试通过并转为 `FROZEN`。
- 未审核账号无法进入主导航，退出后所有内存密钥和会话状态被清理。
