# 应用部署清单

> 当前方案：本文面向公网 ECS + 私有阿里云 OSS 部署。业务服务和 PostgreSQL 位于 ECS，客户端通过 HTTPS 访问，不存在个人电脑或家庭设备部署前提。

## 1. 输入信息

- [ ] 应用名称与 Git 仓库地址
- [ ] 要部署的提交、标签或发行版本
- [ ] 容器镜像来源与校验方式
- [ ] 域名
- [ ] 应用端口
- [ ] 数据库类型与持久化路径
- [ ] 必需的环境变量清单
- [ ] 已阅读[《OSS 身份、ECS RAM Role 与 App 上传授权》](./02-oss-ram-role.md)，确认本地 STS 与 ECS RAM Role 是两种 Service 凭据来源，App 只接收签名 URL

## 2. 安全

- [ ] `.env` 未被 Git 跟踪
- [ ] 应用不使用长期阿里云 AccessKey
- [ ] 数据库仅在容器网络或回环地址监听
- [ ] 公网只开放 SSH、HTTP 和 HTTPS 中确实需要的端口
- [ ] SSH 保持密钥认证，限制高风险登录方式
- [ ] OSS Bucket 保持阻止公共访问
- [ ] 在线应用角色不能列举 Bucket 或全部 multipart，只能访问 `avatars/` 与 `media/` 前缀中的已知对象
- [ ] 应用角色继续显式拒绝永久删除原文件

## 3. 部署

- [ ] 创建独立部署目录
- [ ] 固定镜像或依赖版本
- [ ] 为低内存主机设置容器内存限制
- [ ] 配置健康检查与自动重启策略
- [ ] 配置反向代理
- [ ] 配置 TLS
- [ ] 启动后检查容器状态与日志

## 4. 验收

- [ ] 登录与权限控制正常
- [ ] 上传一张非敏感测试图片
- [ ] 单媒体 multipart 仅获得逐 part 短期 PUT，过期和越权对象键均被拒绝
- [ ] 图片列表与预览正常
- [ ] 原图通过后端受控读取，Bucket 不公开
- [ ] 逻辑回收站行为符合设计
- [ ] 重启容器后数据仍然存在
- [ ] 备份与恢复至少演练一次

## 5. 回滚

- [ ] 记录部署前版本
- [ ] 保留数据库迁移回滚或恢复方案
- [ ] 新版本异常时能恢复旧容器
- [ ] 回滚过程不依赖删除 OSS 原文件
