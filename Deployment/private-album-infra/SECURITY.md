# 安全说明

## vNext 家庭节点约定

- 家庭节点的数据库、对象目录和内部服务端口不得直接暴露公网。
- V0 PostgreSQL 只绑定 `127.0.0.1`，API 8080 只允许指定家庭局域网访问。
- V0 不使用真实账号、真实照片或正式密码，不配置阿里云 OSS。
- 不在路由器上为 V0 配置 8080 或 5432 端口转发。
- 家庭节点注册密钥、长期 DTLS 证书私钥和后续配对材料不得写入仓库或普通日志。
- 部署结果只回传 commit SHA、版本、探针结果和脱敏错误，不回传 `.env` 或容器完整环境变量。

## 不应进入仓库的内容

- AccessKey ID、AccessKey Secret、STS Token
- SSH 私钥、TLS 私钥、数据库密码、应用密钥
- `.env`、阿里云 CLI 配置、ossutil 凭证文件
- 真实实例 ID、账号 ID、Bucket 名、RAM 角色名
- 公网 IP、内部拓扑、未公开域名
- 带有签名参数的临时下载或上传 URL
- 完整请求日志、云平台 Request ID 和错误追踪包

真实运行参数只保存在部署主机的 `.env` 或后续选定的密钥管理服务中。旧 ECS + 阿里云 OSS 架构使用实例 RAM 角色自动获取临时凭证；vNext 家庭节点不再把该方式作为目标对象存储方案。

## 提交前检查

```bash
./scripts/scan-secrets.sh
git diff --cached
```

仓库已经包含可选的提交前钩子。从 MineG 仓库根目录启用：

```bash
git config core.hooksPath Deployment/private-album-infra/.githooks
```

## 如果敏感信息已经提交

1. 立即停止继续推送和分享仓库。
2. 在对应平台撤销或轮换泄露的凭证。
3. 清理 Git 历史，而不只是删除最新版本中的文件。
4. 检查云审计日志，确认是否存在异常调用。
5. 确认旧凭证失效后再恢复部署。

仅把仓库改为私有不能使已经泄露的凭证重新安全。
